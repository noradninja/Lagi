# Venezia audio offload roadmap

Development branch: feature/venezia-audio-offload. Stable merged baseline: 84293e4e5b8af2dfbf3f88b1bfcbfc747f025563; synchronized feature checkpoint: 37f117c83f46331ec7e3ded0969e061c0b18ad9f. Preserve the existing ARM backend, Azel timing, renderer and audio ownership semantics. Atomic commits; developer pulls, builds and validates on Vita hardware.

## 1. Baseline
Consumer instrumentation cbee8b9 restores [LagiPCM] on the feature branch after synchronization with main. Each stream has a serial, sample rate, channel count, block size and monotonic timestamp. Cumulative steadyBlocks, underrunBlocks, emptyBlocks and missingFrames count successfully submitted blocks after startup, excluding finished-stream padding. minQueuedFrames is interval-local. Reports every 128 eligible blocks plus a final partial interval on clean thread exit. Separate streams; difference cumulative counters within a stream, never across restarts. Abrupt termination can lose the last partial interval. This measures software PCM starvation, not every possible hardware or audible discontinuity.

Worker instrumentation 4f100cf reports [AzelAudioWorker] sampled active iteration time including events, commands, DSP service, output lease and rendering/mixing/submission. gapUs is the inter-iteration gap, not a complete scheduler latency measurement; deliberate sleep is excluded. Timestamp commit e601455 adds tUs to sampled worker and synthesis reports. Samples are sparse and may miss spikes; logging itself can perturb timing. Correlate with [AzelAudioPerf]. No compile or hardware validation of the restored instrumentation yet.

44100 Hz, 256-frame synthesis quantum = 5804.99 us; 1024-frame output block = 23.22 ms; target queue 2048 frames = 46.44 ms. Historical 84-step ARM DSP median 2268 us, synthesis median 5297 us (see SCSP_DSP_TRANSLATOR.md); not a fresh measurement. Do not change buffer sizes or scheduling until starvation is characterized.

### Natural-play workload protocol
Identical gameplay replays are not required. Use the same device, clocks, build configuration and ARM backend when practical; record deviations. Play normally across available representative workloads: idle/moving Camp, field traversal, ordinary and busy battles, and transitions (including Cinepak/CDDA when naturally encountered). Aim for roughly 1–2 minutes per available steady workload, preferably with repeat visits; shorter captures are useful and no exact route or timing is required. Exit normally to flush the final interval. Retain full logs and note device, clock overrides, locations and audible issues. Do not require artificial pauses or repeated identical encounters.

### Analysis
- Group output intervals by stream, rate and scene/sequence when identifiable from neighboring log events; mark mixed or ambiguous intervals separately. Treat startup/load/ownership transitions as their own workload rather than hiding them in steady-state averages.
- Normalize missing frames by steadyBlocks * blockFrames (percent or ppm); report underrun blocks per 1000 eligible blocks, empty blocks separately, and queue low-water distributions. Use counter deltas within each stream and weight by observed eligible frames, not number of reports.
- Stratify sampled synthesis cost by sequence, DSP hash/steps/backend and active-slot ranges. Report sample count, median, P95, maximum and fraction exceeding the quantum deadline; do not treat sparse samples as exhaustive. m68k/SCSP component estimates are nested/interleaved, not additive independent wall-clock times.
- Compare worker active time, rendered vs non-rendered samples, lease time and gaps; correlate with PCM reports and existing scene/render timing. Timestamped audio records support temporal correlation, but asynchronous log ordering and sparse samples cannot prove exact per-underrun causation.
- Compare representative distributions and worst cases across workloads, not raw total underruns across different playthroughs. Preserve outliers and note sample sizes. Capture the baseline before implementing MeP execution.

### Step 2A: repair native DSP reselection before MeP work
The 2026-11-25 natural-play capture demonstrates actual PCM starvation and frequent sampled reference execution despite ARM cache hits. Stopped DSP samples also use profiler backend 0, so that category alone is not proof of active interpreter execution.

The pinned Azel SCSP write path triggers SCSPDSP_Start on address 0xBF0, before the last MPRO word at 0xBFE. The old dirty hook cleared the selected native function; worker service only processed pending cache misses. A cache hit followed by an MPRO write could therefore leave a running DSP permanently on the generic path until another Start. Commit 6e140d8 reselects dirty running programs at the existing worker boundary, preserving the LastStep latched by Start and using the reference during modification. Commit 8dcac62 avoids invalidation for identical register writes without suppressing the native Start trigger. Commit 5cb84b1 adds regression coverage for cache-hit Start, changed MPRO, safe reference execution before boundary, native reselection, restoration to a cached program, and no repeat selection on clean service.

Hardware acceptance: [LagiDSPReselect] reports dirty recovery with selected backend (3=ARM); compare active DSP workload backend distributions, PCM starvation and quantum timing against the baseline. Backend 0 can also mean stopped DSP; the 127-step invalid-program rejection is a separate Step 2B issue, not fixed here. Tests and Vita build remain unverified until run. No queue depth, timing, affinity, or MeP changes.

### Step 2B: trace invalid live MPRO after battle restoration

Hardware capture `lagi(20261125-011508).log` and the user's listening test show generally improved playback after Step 2A, with severe degradation on repeated returns to field sequence 7. The log contains five repeats of Start hash `305D2AED` (127 steps) followed by worker reselection hash `7D21076E`, reason `invalid-program`, backend 0. An additional rejected hash `90F949DE` occurs during a sequence 8 transition. One example has 11.055 ms for a 256-frame quantum against a 5.804 ms budget. The Start summary for `305D2AED` has 126 IWT/EWT/ADRL/FRCL and wrap shifts. This suggests malformed or unexpected program data but does not establish the word pattern or its origin. The IR decoder rejects IRA >= 0x32; do not relax this check or force a previously cached program.

Diagnostic-only commits:
- `1cfd3d4`: capture the live rejected program through the existing LDSP queue, including first/last invalid IRA step, invalid count, all-one/zero word counts, first offending instruction, and final MPRO row (including words outside latched LastStep). Deduplicate diagnostics by hash and steps, capped at 16 per process.
- `eabb979`: fingerprint the actual loaded A5DSP.EXB bytes and the corresponding sound-RAM region at battle mark/pop, loader DSP init, area map, bank copy, effect/mixer change, and sequence ready. Compare live to original loaded bytes. These are worker-owned transition observations only.
- `fe93680`: sample changed MPRO writes with invalid IRA at the original SCSP register assignment, including M68K PC, register address, instruction index, and old/new words. Limit four records between Start-trigger writes and 64 overall. Preserve upstream assignment and Start semantics.

Hardware validation: rebuild with existing options (CMake regeneration required for the generated SCSP hook); boot fresh, load a field save, enter/exit multiple battles until audio degrades. Return the log plus newly captured LDSP files in `ux0:data/lagi/dsp_programs/` (especially `305D2AED-127-*.ldsp`, `7D21076E-127-*.ldsp`, `90F949DE-127-*.ldsp` if present). Keep prior captures. Read `[LagiDSPWrite]`, `[LagiDSPReject]`, `[LagiDSPImage]`, and `[LagiDSPReselect]` together. A stable image fingerprint narrows but does not exclude sound-RAM corruption elsewhere; a mismatch establishes a change to the image, not its cause. PC is the sampled core PC at the register write, not necessarily the exact instruction address; correlate against the original sound driver. No timing, queue, affinity, decoder validity, or MeP changes. Build and hardware validation pending; no root-cause repair claimed yet.

### Step 2B repair: area-map-aware sound bank residency

The Disc 1 original AREAMAP.SND contains DSP work areas (type 3) at [0x54000,0x64100) in map 0, [0x48000,0x58100) in map 1, and [0x4E000,0x5E100) in map 2. Both A5DSP.EXB [0x53500,0x53A40) and BTL1DSP.EXB [0x53A40,0x53F80) overlap map 1. In the 2026-11-25 log BTL1DSP.EXB is loaded at line 444, camp sequence 64 uses map 1 at 22077, and Garil sequence 7 uses map 0 at 23688; the loader reloads A5DSP.EXB at 23736 but not BTL1DSP.EXB. The invalid MPRO write is sampled at M68K PC 0x0013CA; rejected AD2809BA has 127/127 invalid IRA fields. This strongly supports stale cached executable residency, but the exact live source pointer and causal repair still need hardware validation.

The repair parses the selected disc's original area-map table at worker startup and evicts all cached files overlapping the selected map's writable DSP range before dispatching the map-change command. A load into active work RAM cannot establish immutable residency. Unknown/malformed maps conservatively disable reuse after selection. EXB entries retain their original bytes and require exact live RAM comparison on cache hits; mismatch evicts the record and reloads through the existing loader. No hard-coded Garil exception, DSP instruction acceptance changes, audio clocks, queue or synchronization changes. Host tests cover map 0 -> 1 -> 0, overlap boundaries, EXB reload after mutation, and the production map command hook. Hardware: verify mapsReady=1, area=1 evicted records, BTL1DSP.EXB reloaded on Garil return, resident-verified EXB hits, and absence of invalid 127-step programs on repeated battle exits. Compare audio timing distributions rather than exact underrun counts. 

### Step 2B hardware result and Step 2C: sequence ownership and replay

Hardware log `lagi(20261125-170411).log` verifies the area-map parser (3 maps), BTL1DSP.EXB reload after Camp, and no invalid-program rejects or invalid MPRO write reports in the capture. User reports post-battle audio generally good, but Valley loses BGM on the second battle exit, train sound is incorrect, and Garil sometimes clicks repeatedly. These are distinct from the previous sustained reference-DSP fallback. Do not undo Step 2B.

Root-cause evidence:
- In the Valley, sequences 1–3 share the local sound table at 0x213340 in original Disc 1 COMMON.DAT. Each has mA=10; valid local IDs 100–109. Sound 100 is [2,0,1,0] (bank, number, replay flag, control slot); 102 is [3,1,0,6]. Sound 111 is out of range. The next table is Garil's at 0x213368. A stale 111 reads into the neighboring table, wrongly selecting bank 2, sound 1, replay flag 1, slot 0. This is consistent with the two erroneous 111 starts at log lines 17285–17286 and missing 100 after the second battle. Checked all 79 COMMON sequence records: each mA-bounded table fits COMMON.DAT, and all declared local records use valid data/control banks 0–7.
- Garil sequence 7 has mA=19; sound 117 is [3,15,0,5]. Pinned Azel 4cebb24b91ed1499b8754cf992c2fc90dbfb044d, AzelLib/field/field_a5/o_fld_a5.cpp, a5ScriptCheckUpdate (06054e34): call findSound(0x75), start only when absent, stop outside visible trigger zones. AzelLib/field/field_a3/o_fld_a3_0.cpp, s_fieldA3_0_task8::Update: findSound(0x66), start positional sound when absent, otherwise update positional volume; stop when no emitter. Both use the original start/update distinction. Pinned audio/soundDriver.cpp updateSoundSub issues start for every explicit start request; do not globally suppress legitimate retriggers.
- Lagi previously compared per-slot sequence ownership to g_requestedSequence set by public loadSoundBanks. worker_pop_sequence restores the parent through worker_load_banks without calling the public API, so the lookup can remain on the battle sequence and falsely report absent loops. The old replay also assigned the entire saved array to live slots and iterated that mutable array while starts rewrote it.

Implementation:
- 9ceefd8: publish worker-completed sequence identity at state 8; invalidate on accepted load/stop, reject local lookup while control events/loading are pending. findSound sees the restored field rather than last requested battle.
- 930f74e: bound local IDs by mA; reconcile live control slots using identical bank, sequence number, slot and residency before publishing ownership; stop/wait for mismatched physical routes as well as changed data banks. Full init invalidates all sequence ownership. Explicit stop/fade removes logical ownership while retaining the physical route for stop/wait. Filter stopped owners out of saved battle snapshots. Immutable replay uses original config +2 flag, prioritizes matching saved slot and starts at most one candidate per destination slot; no fake owner for non-replayed entries. A persistent eligible sound already surviving in its correct slot is not restarted. No blanket suppression of explicit starts.
- Extend production-extracted battle_audio_stack_test.cpp with bounds, stale Valley 111, duplicate/colliding replay, sequence publication, stopped ownership, route reconciliation, simultaneous independent control slots and genuine repeated start cases. Host test execution and full Vita build not yet verified.

Hardware acceptance: fresh boot, Garil -> Valley -> at least two battles; sound 100 continues after each restore, no out-of-range 111 start, [LagiSoundReplay] starts at most once per destination slot. Verify train pass has one start for 102 followed by bank=5 positional volume requests until stop. In Garil, return from battle near a trigger zone: 117 should start once until leaving zone, not every game update. Test leaving/re-entering zones, normal one-shot effects, camp/field transitions, tunnel shared-bank ambience and battle audio. Compare PCM counters and valid DSP hashes; distinguish remaining real underruns from sequence behavior. Correctness first: Step 2D is the corrected ARM baseline before Venezia bridge work. No DSP, clocks, buffer size, affinity, or audio synthesis changes in 2C.

## 2. Bridge feasibility
Upstream: https://github.com/GrapheneCt/VVNZRunner
Inspect pinned source and release artifacts, license and firmware requirements. Measure injection, blocking execution, cache ownership transitions, mapped buffer transfer, warm/cold dispatch, contention and suspend/resume. Use coarse work units, never per-sample bridge calls. Verify ABI and alignment; ARM pointers are not MeP pointers. No assumptions about cache coherence or speed.

## 3. DSP prototype
Compile existing generated straight-line C DSP code with MeP toolchain before investing in a machine-code emitter. Use captured 52/84-step and synthetic 128-step programs. Compare state, output and sound RAM writes against reference, including overflow, addressing and program changes. Benchmark complete round trip, not only execution. Zero correctness mismatches required. Target synthesis under 4 ms per quantum including overhead; aspirational, not measured.

## 4. Combined sound core
Investigate portable 68000 and SCSP core together on Venezia to preserve per-sample CPU/DSP interleaving, RAM and IRQ semantics. Keep ARM control plane and PCM output. Define explicit ownership and synchronization for sound RAM, bank loading, command queues, PCM and state. Validate sequence changes, battle sounds, fades, suspend, movies and shutdown. ARM remains default until acceptance. Fallback before starting a stream; live fallback requires validated state transfer.

## 5. Deployment
Goal: no manual dependency installation. Investigate bundling pinned VVNZRunner kernel module and MeP ELF in VPK, conditional on redistribution permission. Prefer detection of compatible existing module and optional runtime loading through supported taiHEN facilities. Verify optional import resolution before linking a mandatory dependency. Verify firmware compatibility, privileges, module ownership, lifecycle, failure handling and suspend safety. Never unload another application's module. Never silently modify taiHEN configuration. If persistent installation is necessary, require explicit consent, backup, atomic config update, duplicate detection, rollback and clear reboot instructions. Do not bundle or install until license and lifecycle are verified. Unsupported devices or failed initialization use ARM.

## Acceptance
Zero steady-state missing PCM frames in representative gameplay, no correctness mismatches, no gameplay/render regressions, no movie/CDDA ownership regressions. Test handheld Vita and PSTV, plugin absent/present/incompatible, cold launch, relaunch and suspend/resume. Document hardware results and exact commits before enabling optional backend by default.
