## Follow-up: mutation, raster policy and allocation constraints

### Producer hooks and limits of verification
CMakeLists.txt 2908 registers nonzero model offsets for all four LOD slots of each object in a loaded environment cell; 3100 notifies bundle loads when MCB/CGB exists. Registration is prefetch/inventory, not visibility or LOD authority. 5313–5340 patches model VDP1 source and CLUT addresses during bundle relocation; audit ordering relative to snapshot creation before generalizing descriptor identity. The bridge's bundle notification clears inventory but does not explicitly retire every pointer-keyed model. Registration replaces a pointer entry when a new bundle+offset record is created, but does not prove all unregistered models are covered.

The native two-pose morph implementation (src/integration/lagi_native_two_pose_morph.inc) compares radius, vertices, normals and relevant colors, sets m_vertexBuffersDirty and calls retire_native_model only if actual content changes. This is a concrete mutable geometry case: rigid pose changes must not be confused with morph changes. Existing tests/model_registration_test.cpp exercises duplicate registration, explicit retirement, address reuse, and retained old snapshot; source inspected, tests not executed. Existing tests/native_two_pose_morph_test.cpp also found by search; not run. Full destruction/mutation closure remains unverified: upstream is a git submodule extern/Azel (yaz0r/Azel), and connector cannot read its nested files or resolve the gitlink as a file. Do not use upstream HEAD as evidence for the pinned build. Inspect pinned processModel.cpp, kernel/fileBundle.cpp and generated azel_upstream sources in a checkout before enabling persistent reuse for unverified producers. Default to transient/legacy for unproven lifetime. Add explicit lifetime contract for reusable adapter rather than assuming pointer cache is universally safe.

### Raster semantics
neptune_renderer.cpp 13019–13038 identifies Garil cliff geometry by scene mode, 20-quads, object address range and model table offsets. 13083–13095 splits draw runs on cliff policy; ordinary run coalescing also requires texture, ordering, blend state, and contiguous indices. 13364–13420 applies cull-none to cliff runs, keeps scene depth by default, and restores state after replay. View 18 (13007) selectively bypasses depth and disables writes for cliffs; circle override is diagnostic. This is production cull policy plus diagnostic experiments, not merely instrumentation. Proposed adapter-supplied raster policy (inherit/none/front/back cull, explicit depth comparison/write override if required); keep existing exact behavior until validated, do not infer from model size or texture. PMOD color calculation remains per originating command (13058–13066). No generalized sorting across incompatible state or ordered commands.

### Allocation and retirement
6525–6573 reserves up to 2730 subdivision quads for native scenes, not just flight; capacity reuse checks all necessary base, textured, wire and subdivision streams. 6593–6599 calls releaseResidentVdp1Model before replacement when reuse fails; this is the direct caller identified. prepare_vdp1_model is used by live path (9105), Basic Wing initialization (11921), and diagnostic model switching (15317/15333). Existing allocation retention is capacity reuse, not per-resource residency. 11930–11950 reserves an optional 8 MiB texture arena in CDRAM with uncached main-memory fallback; this is not available geometry budget. Frontend finish at 15110–15111 and composite failure at 15938–15939 are additional completion sites. Current successful native frame finishes at 16001 before producer slot release. Failure paths require explicit verification of GPU completion before any arena reuse; do not assume frame number or semaphore alone is a fence.

### 1D design decisions / initial budget proposal
* Begin with a bounded optional transformed-payload cache, opaque resource key and explicit representation version. Producer supplies immutable snapshot identity and compatible transform convention. Geometry, transform, UV/layout, material/texture generations and dynamic shading must be tracked separately; include every dependency of the actual cached payload (including material-dependent UVs if present). Unverified/morph/view-dependent cases use existing path. No new gameplay mode gate. No change to upstream visibility or LOD.
* First arena prototype: provisional 2 MiB total additional mapped geometry budget in uncached main memory, independently configurable; not a measured available budget. No mandatory CDRAM reservation. Allocate lazily after essential resources. Count mapped rounded bytes, not requested payload only; include alignment, fragmentation, metadata and CPU staging separately. Evict least-recently-used unpinned ranges only after GPU completion, never current-frame ranges. If oversized, full or allocation fails, keep legacy path; select fallback before emitting affected draws to avoid duplicates. No extra per-draw finish. Revisit budget using real resident-byte distribution, eviction rate and memory headroom; do not increase solely to improve cache hit rate. Keep baseline buffers initially, then consider reducing duplicate storage only after acceptance.
* Initial integration gate: host tests for key equality/revision/coordinate changes, address reuse and retirement, morph rejection/revision, range bounds and U16 local indexing, arena allocation/free/coalescing, pin/evict, allocation failure, and ordered draw descriptor equivalence. Add sampled telemetry for requested/resident/mapped bytes, high-water, fragmentation, uploads, evictions, fallback reason and draw count. Preserve existing synchronized GPU completion initially. Capture Garil, Valley, town, battle, cutscene and repeated transitions. Proposed targets: no visual regressions; no material/priority/order divergence; no leaks or extra misses in Valley; improve heavy-frame build toward 2–3 ms and maintain 1C.2 CRAM performance; aim 99.5% presentation deadlines, not a guaranteed result.

### Audit disposition
Renderer-side design is sufficient to specify a conservative 1D.1 resource-contract prototype, but full 1D.0 closure is conditional on pinned upstream destruction/mutation review, error-path GPU completion review, and measured memory baseline. Keep runtime unchanged until these are resolved or explicitly bounded by legacy fallback. No Disc archive needed for these source checks, no compilation or hardware test performed.
