# Field geometry cache investigation

Branch from main fff37ab (quiet ARM audio baseline). Preserve existing visuals, full resolution, original Azel culling/LOD decisions, collision, lighting and VDP1 ordering.

## Source trace
Pinned Azel 4cebb24b: FLD_A5 subfield setup calls readDataTable3; readEnvironmentGridCell reads 24-byte placement records and five 16-bit model offsets, four render ranges plus collision. gridCellDraw_normal in field/field_a3/o_fld_a3.cpp chooses a model using camera-space depth (default 8,16,32 in 16.16 units), skips zero offsets, and submits the selected variant. get3DModel caches by bundle offset. Lagi CMake generated field submission hook supplies original cell/record address, selected offset, world matrix and fieldEnvironment. Render bridge supplies model generation. Neptune hashes the entire static sequence (including variant and matrix); any difference clears and reconstructs static CPU prefix and invalidates subdivision positions. Existing material cache and GPU allocation reuse do not guarantee retained geometry contents.

## 1A — observational classifier
Enable -DLAGI_FIELD_CACHE_TRACE=ON on this branch. Default OFF; no normal-build overhead. Keep audio diagnostics, GPU serialized pass timing and field motion trace OFF. One [FieldCacheWindow] record per 120 successful native field builds. Count visible static placement differences by stable (bundle,cell,object) tuple and separate variant offset. Duplicate keys are ambiguous rather than guessed. LOD means different selected offset for a surviving explicit placement, not a claim about the underlying distance threshold. Same-offset model identity/generation/polygon count changes count as resource changes. Matrix changes independently count transform. Relative order of common placements is tested excluding additions/removals. Entry/exit includes visibility, absent LOD and streaming; cannot separate those with published visible submissions alone. Rebuild without observed field-placement delta is unclassified (e.g. other static submissions). Categories overlap; counts are not exclusive. First snapshot is baseline; scene-mode ownership reset discards partial windows and history. Same-mode subfield changes may appear as entry/exit or resource changes; do not treat them as steady-state LOD samples. Classification happens only on rebuild or first snapshot. classificationUs is total observed classifier time, included in build times. Compare with trace OFF before attributing speed differences. No cache behavior changed.

## 1B — persistent prepared placement vertices

Hardware 1A capture 2026-11-26: 7,320 field builds, 627 rebuilds, 560 entry/exit frames, 151 LOD-change frames (182 switches), 1,205 entries/exits. No same-offset resource, surviving-transform or relative-order changes observed. 724 of 1,257 individually logged three-vblank misses were on retained-prefix frames; do not expect 1B to solve stable-frame costs.

LAGI_FIELD_PLACEMENT_CACHE=ON by default; OFF restores old append behavior for A/B. Cache only explicit rigid native field environment submissions, centered origin, valid versioned model, no billboard or animated colors. Key includes opaque native model identity/generation, bundle/cell/object, selected model-table offset, exact 12-component world matrix, vertex and polygon counts. No pointers into published frame arrays retained. A miss stores the exact transformed vertex range produced by the existing canonical append path; a hit bulk copies it into current flattened positions. The existing adapted model already owns immutable polygon descriptors and the material cache owns texture indices, so do not duplicate these; keep per-frame polygon rebasing, light payloads, shade initialization, mesh ranges, texture refresh and Azel ordering on the original path. Scene-mode epoch clears cache; same-mode resource generations prevent stale address reuse. Bounded LRU: 4 MiB exact retained vertex arrays, at most 512 entries (metadata additional), no new GPU allocations. Eviction only during insertion. Dynamic/shifted/non-field objects unchanged. Static prefix rebuild remains required for visible-set changes; 1C/1D will address subdivision and GPU rewriting.

With LAGI_FIELD_CACHE_TRACE=ON, [FieldPlacementWindow] records every 120 successful field builds: hits/misses/stored/bypass count static append attempts only, hitVerts/missVerts count expanded vertices, entries/bytes/peakBytes track payload residency, evictions count window delta, lookupUs/storeUs measure cache overhead. Compare FieldCacheWindow rebuildMeanUs and FlightPresentWindow with similar workload; no promise of identical runs. Acceptance: return to previous LOD and camera region yields hits, bounded memory, no changes in visible meshes/textures, lighting, blend order or collisions. Check both fast and slow Garil, corridor, battle return, Camp and another field. No device test yet.

## 1C — retain invariant subdivision payloads (first implementation)

1B hardware capture 2026-11-26: 3,120 builds, 594 rebuilds, 21,611 hits / 240 misses (98.90%), 1,915,404 reused expanded vertices, 402.2 KiB peak vertex payload, zero evictions. User confirmed no visual regression. Weighted rebuilt build time 6.882 ms vs 8.644 ms in unmatched 1A capture; not a controlled benchmark.

LAGI_FIELD_SUBDIV_CACHE=ON by default (OFF for A/B). In normal field FULL mode, retain exact physical subdivision-slot XYZ identity using all twelve source-corner float bits. The existing validity flag is still reset on rebuild/prepare; only when it would require a write can an exact match suppress the XYZ midpoint evaluation and mapped writes. Offscreen slots retain their actual last-written identity, dynamic overwrites invalidate it, non-FULL/non-field draws and scene/storage boundaries clear tags. Shade calculation and corner-bit shade reuse remain independent. Shared bounded 64-entry UV templates keyed by actual decoded dimensions and both Saturn flip bits; use the existing midpoint arithmetic, including half-texel inset. Existing per-slot UV validity remains authoritative. Keep initialized absolute 24-index topology through field shrink/regrow; release still clears storage. No new mapped GPU buffers, no culling, material, ordering or shader changes. At most 2730 slot records (about 139 KiB assuming 52-byte record) plus ~5.3 KiB UV templates. Relocated quads still require XYZ writes; do not store a duplicate expanded grid for every variant before measuring whether the additional copying beats midpoint arithmetic. Persistent range allocation is 1D.

With trace ON, FieldSubdivWindow per 120 renderer frames counts static XYZ candidates/reused/writes (excluding already-valid slots and dynamic writes), UV slot skips/template hits/misses/writes, topology quads initialized, sum of subdivision prepare and full Gouraud payload wall times. Compare with 1B FieldStream subBuild and ScenePerf gourPayload; timestamps include other work. Verify camera rotation, LOD, disappear/reappear, battle return and Camp. ## 1C follow-up — decouple clean field texture invalidation before 1D

The 1C capture had 2,751 FieldTextureUpload calls, 2,698 with zero uploads. User reports Valley flight already holds steady FPS; do not assume Garil's bottleneck is universal. No matched Valley invalidation capture yet. Source trace: applyPendingRendererInvalidation consumes CRAM/VDP1 flags (also SPCTL format transitions), advances texture generations, and historically clears g_liveTownSignature and g_liveTownPrepared and sets global dirty unconditionally. buildLiveTownFrame refreshes stale referenced decoded materials; then dirty, unprepared, signature change, atlas size change or missing base payload all call prepare_vdp1_model. Thus a write affecting only VDP2 or an inactive texture can force geometry preparation and full atlas upload validation even with zero changed active texels. Dynamic polygon count and ordered texture-index changes also affect the combined signature even with a retained static prefix.

LAGI_FIELD_TEXTURE_DECOUPLE=ON (OFF for A/B): only a clean, prepared, resident FULL field defers unconditional dirty/signature reset for texture-only invalidations. Generation dependency checks, VDP1 material-cache invalidation and UI invalidation remain intact. Stale referenced materials decode as before, set dirty, and take original upload/prepare path. Active GPU/decoded generation mismatches also set dirty in live scenes, including after mode transitions; atlas count changes and geometry signature changes still force preparation. Dirty or unprepared fallback, non-field, non-FULL invalidation behavior unchanged. No changes to geometry layout, texture pixels/filter, light, shade or ordering. Skip redundant prefix descriptor scan on field prepare when reuseTextures is already true (upload branch is skipped, release preservation is already true). Retain full prefix validation for dirty or growing atlases. No claim that this eliminates all historical texture walks: invalidation dependency scan and genuine refresh/upload path remain. No GPU range changes yet.

FieldPrepareWindow (trace ON): counts successful field builds per 120; cram/vdp1/format count consumed flags (not individual writes), deferred counts frames taking clean field deferral, prepared/signature/dirty/count/notReady/base are overlapping pre-prepare reasons, uploadCalls/zeroUploads/uploaded cover prepare path only, refreshed counts active CPU decodes, prefixSkipped counts redundant prefix comparisons bypassed, invalidateUs/uploadUs aggregate observed timing, textures current retained count. Compare Garil and Valley with the same flags, examine actual subfield transitions; verify palette animation, material reload, battle return, LOD and no new visual regressions. 1D remains separate. No full Vita build/device test performed.
