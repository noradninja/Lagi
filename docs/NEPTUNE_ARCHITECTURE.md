# Neptune architecture and optimization direction

## Scope
Neptune is a reusable native rendering framework for Sega Saturn game ports to PlayStation Vita. Lagi is its first consumer. Portability means reuse across Saturn games on Vita, not portability across hardware. SceGxm, SGX543MP4+ and Vita-specific memory and synchronization optimizations are encouraged; a cross-platform backend abstraction is not a goal.

Azel decides; Neptune renders. Game adapters own gameplay, camera, visibility, LOD selection, animation, asset loading and game-specific policies. Neptune owns Saturn rendering semantics, VDP1/VDP2 primitives and composition, texture decoding, CRAM dependencies, geometry residency, shading and GXM resources. Eligibility for optimization must depend on rendering properties, not scene names, disc assets or gameplay modes. Garil Desert is a stress test, not a special-case target. Preserve original ordering, priority, color calculation, clipping and shading.

## Current checkpoint
1C.2 (0cd5ec020f03f50978197e9b89c54f07f7f68a3d) was hardware tested on 2026-11-27. User reports significantly improved Garil performance and unchanged Valley performance. Prior capture analysis reported approximately 0.102 ms CRAM invalidation versus 1.41–1.56 ms previously, 3633 fast paths and no fallbacks, 99.05% placement hits, and 28.39 average presentation FPS. These are observational, non-identical runs, not controlled A/B benchmarks. Existing field-only gates are transitional validation boundaries, not final architecture. Defer 1C.3 material cleanup pending profiling.

## 1D roadmap
- 1D.0: Read-only audit of game/mode dependencies, submission paths, resource identity, mutation, lifetime, ordering and synchronization. Produce a gate inventory and eligibility contract before implementation.
- 1D.1: Generalized geometry resource identity and lifetime management, separating immutable geometry, instance transforms, dynamic shading and material state.
- 1D.2: Persistent GXM geometry ranges with bounded memory, safe retirement and fallback.
- 1D.3: Submit resident ranges in authoritative order without rebuilding combined meshes when visibility changes.
- 1D.4: Generalize placement, subdivision and texture optimizations by capability, preserving legacy fallback until validated.
- 1D.5: Validate town, flight, battle and in-engine cutscenes, including transitions, palette animation, LOD, dynamic lighting and memory pressure.

## Audit acceptance
Identify every relevant gate and its safety rationale; distinguish game policy from renderer invariants. Map resource producers and consumers, stable identity and generation changes, VDP1/CRAM writes, SPCTL changes, scene teardown, in-flight GPU ownership and buffer reuse. Define eligibility for rigid meshes, rigid animated hierarchy parts, deforming geometry, billboards and transient primitives. Preserve Azel submission decisions and Saturn compositing semantics. Record baseline timing, deadline misses, rebuild causes, cache hits, bytes uploaded and memory high-water marks. Use independent switches and atomic commits; do not remove existing safety gates before replacement invariants and hardware tests exist. No renderer implementation changes are authorized by the audit alone.

## Naming and ownership convention
Use neptune::, include/neptune/ and NEPTUNE_ for genuinely reusable rendering systems; retain lagi::, LAGI_ and azel_bridge:: for game/application integration. Keep Saturn hardware terminology and Vita/GXM implementation names. Rename misleading town/field terminology incrementally when touching a shared subsystem, in mechanical commits separate from behavior changes. Do not disguise game-specific policy with generic names or remove guards simply to rename them. Preserve compatibility aliases for renamed public build flags and update tests/diagnostics/documents. Existing shared buildLiveTownFrame, LiveTown residency and field cache naming are audit candidates, not blanket rename authorization.

## 1D.1A checkpoint
065fa49 adds include/neptune/geometry_resource_key.h; e993c6e adds a standalone key test. Resource identity consists of nonzero producer namespace, opaque resource ID and revision. The representation key adds versioned layout and coordinate convention, local/transformed space, exact fixed-point transform for transformed payloads, and a baked-attribute dependency revision. Local keys require a canonical zero transform. Full equality, not hash alone, controls reuse. Zero/invalid keys must fall back; key validity alone does not prove eligibility. Producer must supply revisions for every baked dependency and not reuse namespace/resource/revision for different content. No raw pointer, scene mode, bundle, cell, object or game identifier is required. Owner retirement, namespace allocation, explicit dependency version production and bounded GPU allocations are later steps; no runtime consumers yet. Host test can be compiled with C++17 or newer (MSVC developer shell: cl /nologo /std:c++17 /EHsc /Iinclude tests/neptune_geometry_resource_key_test.cpp). A local equivalent source copy passed GCC C++17 with warnings as errors; no Vita build or hardware run.

## 1D.2 allocation and shadow residency checkpoint
Hardware observation from the 2026-11-27 run was accepted by the user (no noted visual regressions; occasional field/combat misses). Revise the original 2 MiB uncached-main-memory proposal to an optional 8 MiB CDRAM-first allocation, with configurable 1–32 MiB budget and uncached-main-memory fallback. Physical 128 MiB CDRAM is not a measurement of allocatable headroom. 2d286b4 introduces bounded aligned range metadata, unique handles within an arena lifetime, first-fit reuse and explicit serial-based deferred reclamation. cbed3c5 tests alignment, overflow, stale handles, range capacity, fragmentation and retirement; exact Git-blob-matched local copies passed GCC C++17 -Wall -Wextra -Werror -pedantic. Handles are arena-local and may not cross arena lifetimes; backend must ensure base alignment and protect all in-flight ranges before enabling real draws. No assumption that a frame number is a GPU fence.

12e74bc adds NEPTUNE_GEOMETRY_ARENA_PROBE (default OFF) and NEPTUNE_GEOMETRY_ARENA_MIB (default 8); db57792 and f92f746 allocate lazily on first shared native scene preparation, CDRAM first, then uncached main memory. A failed optional allocation leaves rendering unchanged. Release after renderer thread stops, before GXM teardown. The block is never bound to GXM or written during this probe. 9b4346d and 1111c46 add bounded shadow LRU metadata over sampled geometry candidates, pin all current-sample entries before eviction, and combine estimated position and hypothetical subdivision bytes (64-byte offset alignment). 1024 range metadata limit; samples use existing 120-publication observation cadence. No payload upload, no resident draw, no modification of texture or geometry ownership. These counts are sampled estimates, not actual cache hit rates or GPU allocation high-water. Sampled candidates do not capture every placement/LOD between observations or dynamic local-space geometry; existing six-quad exclusion and provisional identity still apply. Shadow LRU is diagnostic, not a production eviction policy. Real retirement remains gated on verified GPU finish/error paths and adapter lifetime/dependency revisions.

Hardware checkpoint: configure existing flags plus -DNEPTUNE_GEOMETRY_OBSERVE=ON -DNEPTUNE_GEOMETRY_ARENA_PROBE=ON -DNEPTUNE_GEOMETRY_ARENA_MIB=8. Check [NeptuneGeometryArena] requestedBytes/mappedBytes/ready/cdram/allocUs, then [NeptuneGeometryArenaSample] estimatedBytes/peakEstimatedBytes/largestFree/ranges/hits/misses/evicted/skipped/sampleUs. Test ordinary flight, heavy combat, town/Camp, transitions and clean quit/relaunch. Observe unrelated texture allocation failures and visual/performance regressions. This build measures allocation success under the existing workload, not remaining free memory, GPU bandwidth or production residency performance. Vita compile and device verification outstanding. Stop at this checkpoint before actual persistent transformed payloads (1D.2C), rather than write/reuse live GPU buffers on unverified lifetime/finish assumptions. Local-space residency for rigid animated models remains an explicit later goal.

## First SGX resident topology checkpoint
The 16 MiB geometry arena and CPU-only transformed vertex probe were accepted on hardware in the preceding run (zero observed comparison mismatches). Disable exhaustive payload verification for performance tests. The first actual GXM resident submission is deliberately limited to invariant 3x3 subdivision index topology, rather than model-dependent vertex payloads. The shared versioned-by-code U16 topology is identical to the legacy grid, with 9 vertices and 24 indices per quad, at most 7281 complete quads, 174744 indices and 349488 bytes. It is written once to a dedicated renderer-lifetime range in the existing mapped arena, never mutated or recycled while GXM can consume it. Shadow observation is metadata only; CPU payload probe is mutually exclusive because its physical offsets would otherwise overlap. Native ordered subdivision draws use the same run offsets, counts, vertex streams, visibility, PMOD, material and raster state. Legacy index copying remains the fallback when allocation or eligibility fails. The existing GXM finish boundaries remain unchanged; arena release is moved after context destruction during shutdown, following render thread join and existing launcher release finish. No per-model GPU retirement or producer mutation hook is claimed: those remain prerequisites to resident vertex payloads. Host regression source checks all index values and U16 bounds; host execution and Vita compile/hardware validation outstanding. Enable NEPTUNE_GEOMETRY_ARENA_PROBE=ON, NEPTUNE_GEOMETRY_ARENA_MIB=16, NEPTUNE_RESIDENT_SUBDIV_INDICES=ON, NEPTUNE_GEOMETRY_PAYLOAD_PROBE=OFF; keep NEPTUNE_GEOMETRY_OBSERVE=ON for comparison. Inspect NeptuneResidentTopology (ready=1, bytes=349488, cdram=1), NeptuneResidentTopologyFrame (aggregate interval draws/indices and fallbacks), normal timing and visual correctness in flight, combat, town, camp, transitions, clean shutdown/relaunch. This tests actual SGX index consumption, not model-vertex residency or elimination of combined geometry assembly. Do not infer improvement from non-identical runs. Keep independent rollback option. 

## Split subdivision stream checkpoint
After the resident index capture, the next isolated hardware test binds two streams to the existing subdivision vertex shader (same GXP, same position/UV/shade parameters and fragment programs). Stream 0 is XYZ+UV (20-byte stride), stream 1 is signed Gouraud RGB (12-byte stride). Separate renderer-lifetime ranges are allocated after the immutable topology range in the same physical arena, not from the shadow estimator. Maximum 65529 vertices reserve 1310580 bytes for geometry and 786348 bytes for shade, plus alignment. The legacy interleaved stream is still maintained and serves as fallback if allocation, program creation, or initial stream binding fails. Canonical preparation and submission updates are mirrored, using the same position, UV and shade validity decisions, including storage recreation. Sprite/UI and other non-native-ordered paths retain their existing stream binding. This is a layout/equivalence checkpoint: the geometry stream remains flattened and mutable, not yet a per-model persistent vertex cache. Expect no claimed speedup and potentially a modest temporary write cost. Host stream ABI test compiled with GCC C++17 strict warnings and passed (source hashes match repository blobs). Vita build and visual equivalence are unverified. Enable NEPTUNE_SPLIT_SUBDIV_STREAMS=ON with resident indices ON and CPU payload probe OFF. Inspect NeptuneSplitProgram, NeptuneSplitStreams, NeptuneSplitStreamsWindow, resident topology and existing timing counters. Watch for shade, UV, clipping, transparency, mesh, palette/LOD, cutscene and sprite-composite regressions; exercise switching views and clean relaunch. Presentation outliers and 120-frame windows now include publication frame, scene mode and monotonic process time to aid correlation with HDMI capture (a common visible event is still needed to establish the video offset; process time is not a wall-clock timestamp). Next: eliminate mirrored writes after equivalence is proven, then model-owned position/UV ranges with explicit retirement and ordered draw offsets. No claim of model resource mutation or GPU-aware retirement integration at this checkpoint.

## 1D.3A.1 Primary subdivision storage
The split stream capture was visually accepted by the hardware tester, with ready=1 for both GXM program and mapped streams and no reported split fallback. Introduce NEPTUNE_SPLIT_SUBDIV_PRIMARY (requires NEPTUNE_SPLIT_SUBDIV_STREAMS) independently of the accepted split-mirror option. When the split program and buffers are available for the prepared allocation, split XYZ/UV and Gouraud streams are authoritative across all view changes. Preparation skips writing duplicate interleaved XYZ/UV/initial shade, and submission skips duplicate position/shade updates. The legacy interleaved allocation remains in place. If the current draw cannot bind split streams, or uses a legacy subdivided diagnostic path, reconstruct the complete interleaved payload of each visible quad before submission, including unchanged fields; do not depend on stale legacy values or read legacy validity metadata as payload authority. Debug position/shade reads follow primary storage. The previous canonical per-slot UV/position/shade validity rules and GXM synchronization remain unchanged. Storage is renderer-lifetime, not per-model residency. Existing geometry preparation, visibility, order, texture semantics and shader mathematics are not otherwise modified. Shared ABI and fallback repacking regression passed with GCC C++17 -Wall -Wextra -Werror -pedantic after verifying both local source Git blob hashes match committed header 5a71ceeec1300a332045244caf80378231a2e8ce and test afc67abadb148b75d118ab9e6c6a2f7f706ea05f. Vita compile and actual draw/diagnostic transition equivalence remain to be tested. Keep arena 16 MiB; CPU payload probe OFF; resident indices, split streams and primary split ON. NeptuneSplitPrimaryWindow reports skipped duplicate write bytes on split path (plus skipped preparation bytes) and legacy repack bytes, not GPU bandwidth. Test Full gameplay and transitions across field, battle, Camp, town and in-engine sequences; deliberately switch to subdivided grayscale (views 10/12) and return to FULL; check shade, UV, clipping, transparency and world sprite/UI composition. The next step after acceptance is a single physical allocation domain for renderer-owned and model-owned ranges, explicit versioned producer ownership/retirement, and local index/stream offsets for ordered draws; the present change does not yet eliminate flattened model assembly. Avoid enabling new resident model draws before proving lifetime and fallback rules.
